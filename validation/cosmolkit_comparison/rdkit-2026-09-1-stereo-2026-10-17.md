# RDKit 2026.09.1 / COSMolKit 0.5.0 stereochemistry comparison

This source-built comparison starts from CheMatic main `f20304f4699ee803ab993f73b98c3c8be38b58fc`.
RDKit 2026.09.1 and COSMolKit 0.5.0 were installed in the same Python 3.13
environment. The base CheMatic CLI SHA-256 was
`97289c62835b9a49f6836bc8f70079905d8caf31d734b7b2ce8a9991ea6368e9`;
the candidate CLI SHA-256 is
`883646776a94c43a499b8593e3a4a5aa288ba4acf13df2e9caf764b7cda1a4e9`.
The Python extension used for CIP comparison SHA-256 was
`2a855f338bb4759fb4aa1021068dce872fa671673237e9c9b085d2e1c07c3da3`.
These are source builds, not published package measurements.

## V3000 writer and read-back

`scripts/compare_rdkit_cosmolkit_v3000.py` parses each source with RDKit,
gives all three writers the same RDKit-normalized SMILES, then asks RDKit to
read each V3000 block back. Exact canonical isomeric SMILES is required;
refusals and changed stereo count as misses. The ChEMBL development corpus
`scripts/chembl_accuracy_corpus_4999.smi` has 5,000 lines (SHA-256
`1c47371dcbe37f4e0a141bf545b72bf238de2761fa3894fa251a552d84728d3e`).

| Writer | Exact identity / comparable | Stereo-token identity / 1,670 |
| --- | ---: | ---: |
| CheMatic candidate | **5,000 / 5,000** | **1,670 / 1,670** |
| RDKit 2026.09.1 | 4,981 / 5,000 | 1,651 / 1,670 |
| COSMolKit 0.5.0 | 4,993 / 5,000 | 1,663 / 1,670 |

All seven COSMolKit misses are also RDKit misses: the read-back changes an
alkene configuration in a related group of conjugated macrocycles (source
lines 67, 110, 111, 112, 117, 146, and 259). RDKit alone also loses a
tetrahedral tag in 12 peroxide-bridged cage molecules (lines 672, 678, 686,
796, 891, 961, 962, 970, 976, 977, 978, and 979). The [base
report](results/v3000-chembl-5000-rdkit2026-2026-10-17.json.gz) and
[candidate report](results/v3000-chembl-5000-concrete-hcount-2026-10-17.json.gz)
retain the input, expected identity, read-back identity, block hash, versions
and binary hash for every record. The candidate changes 1,644 CheMatic blocks
without changing any ChEMBL identity under RDKit read-back.

### CheMatic block read by COSMolKit

Some COSMolKit V3000 reads classified a CheMatic block containing redundant
`HCOUNT` as a query graph rather than a concrete molecule. The candidate omits
that property for neutral aliphatic carbon when ordinary bond valence supplies
the same H count, and for pyrrole-like `[nH]` with two ring bonds. It retains
nonredundant counts such as radical `[CH]`. COSMolKit's `from_mol` result is
converted to SMILES and normalized by RDKit before the exact comparison.

| Corpus | Eligible | CheMatic block → RDKit | CheMatic block → COSMolKit |
| --- | ---: | ---: | ---: |
| ChEMBL | 5,000 | 5,000 | **5,000** |
| Browser 10k | 10,000 | 10,000 | 9,952 |
| `stress-v1` | 4,070 | 4,025 | 3,345 |
| Focused V3000 stereo | 316 | 316 | 258 |
| Stereo torture development | 300 | 300 | 300 |
| NCI negative control | 4,991 | 4,991 | 4,943 |

The [browser](results/v3000-browser-10k-concrete-hcount-2026-10-17.json.gz),
[stress](results/v3000-stress-4070-concrete-hcount-2026-10-17.json.gz),
[focused stereo](results/v3000-stereo-316-concrete-hcount-2026-10-17.json.gz),
[stereo torture](results/v3000-stereo-torture-300-concrete-hcount-2026-10-17.json.gz),
and [NCI](results/v3000-nci-4991-concrete-hcount-2026-10-17.json.gz)
candidate reports retain each reader's per-row outcome. COSMolKit still
classifies some CheMatic blocks in those corpora as query-bearing, so the
ChEMBL result does not establish general cross-reader compatibility.

The separate 300-molecule [stereo torture development
corpus](../stereo_torture_suite_development.jsonl) gave CheMatic 300/300 and
both other writers 299/300; their common miss is `stereo-dev-206`, another
macrocycle ([row report](results/v3000-stereo-torture-300-rdkit2026-2026-10-17.json.gz)).
The NCI 5k negative control had 4,991 comparable rows and all three writers
passed all 4,991. Its eight exclusions were source-normalization failures;
it has no stereo-token rows, so it does not support a stereo lead
([row report](results/v3000-nci-4999-rdkit2026-2026-10-17.json.gz)).

## CIP labels and 3D recognition

The CIP audit now keys double-bond assignments by their atom endpoints and
compares RDKit's `_CIPCode` with CheMatic's E/Z assignment. Keying CheMatic's
bond by `atom_idx` and reading RDKit's cis/trans tag had produced five false
mismatches in the 300-molecule stereo development corpus. After correction,
the 300 rows agree on 733 atom labels and 48 bond labels. The 5,000 ChEMBL
rows agree on 4,186 atom labels and 678 bond labels; both CheMatic and
COSMolKit match RDKit's complete per-molecule CIP output on 5,000/5,000
rows. The [focused audit](results/cip-chembl-5000-rdkit2026-2026-10-17.json)
and [three-engine summary](results/cip-chembl-5000-three-engine-2026-10-17.json)
retain the counts and versions.

On `stress-v1.smi` (4,072 rows), CheMatic matches RDKit's CIP output on
4,070 rows and COSMolKit on 4,066 rows. COSMolKit cannot parse six sources.
CheMatic instead abstains at two stereocenters with a directly attached
wildcard ligand (source indices 1956 and 3618), with the typed
`oracle_unstable` reason. RDKit and COSMolKit return R/S there. An unspecified
element does not have a fixed CIP priority, so those assignments are not
accepted as chemical ground truth. The [stress
summary](results/cip-stress-4072-three-engine-2026-10-17.json) retains the
engine status counts. CheMatic's correct-row set is not a superset here.

For a selected ChEMBL sample of 50 tetrahedral and 50 alkene structures,
RDKit 2026.09.1 embedded and self-validated unmarked 3D V2000 and V3000
records. CheMatic and COSMolKit each recovered 100/100 exact identities in
both formats. The [selection
manifest](results/unmarked3d-chembl-100-rdkit2026-2026-10-17-manifest.json)
and [report](results/unmarked3d-chembl-100-rdkit2026-2026-10-17-report.json)
retain the source indices and generated SDF hashes. RDKit is the source and
read-back gate in this lane, so it is not an independent RDKit recognition
comparison.

## Reproduction and limits

From the repository root, with RDKit 2026.09.1 and COSMolKit 0.5.0 installed:

```sh
cargo build -p chematic-cli --bin chematic --offline
maturin develop --manifest-path crates/chematic-py/Cargo.toml --offline
python scripts/compare_rdkit_cosmolkit_v3000.py \
  --corpus scripts/chembl_accuracy_corpus_4999.smi \
  --cli target/debug/chematic --report /tmp/chembl-v3000.json
python scripts/cip_label_parity_audit.py \
  --corpus scripts/chembl_accuracy_corpus_4999.smi \
  --expected-rdkit 2026.09.1 --output /tmp/chembl-cip.json
for engine in rdkit cosmolkit chematic; do
  python validation/cosmolkit_comparison/run_corpus.py \
    --engine "$engine" --corpus scripts/chembl_accuracy_corpus_4999.smi \
    --output "/tmp/$engine-cip.jsonl" --skip-ops '^(?!cip$).*$'
done
python validation/cosmolkit_comparison/compare_corpus.py \
  --reference rdkit=/tmp/rdkit-cip.jsonl \
  --engine cosmolkit=/tmp/cosmolkit-cip.jsonl \
  --engine chematic=/tmp/chematic-cip.jsonl \
  --output /tmp/three-engine-cip.json
cargo build -p chematic-mol --example sdf_v3000_accuracy_dump --offline
python validation/cosmolkit_comparison/check_unmarked_3d_stereo.py \
  --corpus scripts/chembl_accuracy_corpus_4999.smi \
  --chematic target/debug/examples/sdf_v3000_accuracy_dump \
  --output-prefix /tmp/chembl-unmarked3d --seed 20261017 --per-category 50
```

The writer corpus and stereo torture suite are exposed development data.
RDKit normalizes the input and judges the read-back, so this tests molecular
identity under that oracle rather than independent chemical truth. It shows a
measured lead on this V3000 writer operation, parity on the tested ChEMBL CIP
and unmarked 3D readers, and two intentional CheMatic CIP abstentions. It does
not establish toolkit-wide or unseen-data superiority.
