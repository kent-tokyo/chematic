## BioTransformer BTMR1031: same products, RDKit cannot re-sanitize its own

BTMR1031 hydroxylates a ring the template writes in Kekulé form. On a
naphthalene the other ring keeps aromatic atoms joined to the rewritten ring
by order-less `~` bonds. RDKit's `SanitizeMol` accepts that product and
perceives the whole system as aromatic; the harness's `RemoveHs` then
sanitizes it again and RDKit's kekulizer fails on the `~` bonds ("explicit
valence 5"). Compared after a single sanitize, with each atom's hydrogen
count written explicitly (chematic's product spells one carbon `[C]` with
an explicit H atom, which RDKit then writes `[cH]`), chematic's products are
RDKit's. No chematic code changed. The harness now types this outcome:

## Cyclophosphazene phosphorus: labelled as RDKit does

The accurate CIP engine had reported phosphorus on a ring that carries a
double bond as `OracleUnstable`, because RDKit's CIPLabeler flips the label
between the ring's neutral Kekulé spellings. It now gives RDKit's label:

| | Batch 9 | Source |
|---|---:|---:|
| ChEMBL 5k labels agreeing with RDKit / abstentions | 4,166 / 20 | **4,186 / 0** |
| exposed 10k | 4,394 / 1 | 4,394 / 1 (the bridgehead amine) |
| 12 P molecules (cyclophosphazenes, phospholene and phosphinine oxides, cyclic phosphonates, benzoxaphosphinine) × 40 spellings, half Kekulé | — | 520/520 agree |

The label still depends on the spelling, in both libraries. Python
`cip_stereo(mode="accurate")` marks such entries `"kekule_dependent": True`
(WASM `"kekuleDependent": true`; Rust
`chematic_chem::cip_label_depends_on_kekule_spelling`), and identity
deduplication still refuses to tell two inputs apart by such a label
(`AccurateCipOracleUnstable`).

## RDKit's ring order, and MMFF94 typing

RDKit's MMFF aromaticity pass walks `RingInfo` in RDKit's order and stops
once every ring atom has been looked at, so a ring deferred until its
neighbours are typed is decided by where it sits in that order. chematic
sorted rings by size; `chematic_perception::rdkit_sssr_ring_order` now ports
RDKit's `findSSSR`/`symmetrizeSSSR` (with libstdc++'s `std::sort` for the
extra-ring pass, as RDKit's Linux builds use) and the MMFF pass takes rings
in that order. It also counts, as RDKit does, only rings accepted so far
toward an exocyclic double bond: RDKit kekulizes with the aromatic flags
cleared, so the input's flags count for nothing.
