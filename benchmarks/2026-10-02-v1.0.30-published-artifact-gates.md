## Full chemistry and output identity

The independent archived-output checker passes across the Python, npm/WASM,
and crates.io Rust artifacts. Each completes 10,000/10,000 inputs, with zero
parse failures. Each has 9,995 exact CIP rows plus five typed abstentions,
9,999 exact compatible-Morgan rows plus one typed refusal, and 200 different
SMARTS cells out of 310,000. The three bindings agree on the same canonical
strings, CIP labels/reasons, Morgan bits, and SMARTS booleans in this cohort.
The npm JSON spells two CIP reason values in camelCase; the checker explicitly
normalizes those names, without changing their meaning.

The [Python raw chemistry rows](../validation/results/v1.0.30-published-python-chemistry-rows.jsonl.gz)
were recomputed from the **published 1.0.30 wheel**. Their uncompressed SHA-256
is `e9b8592b69a0663608ab51d0d83d3db644a515a7cbfedefe5ad5aff61780b968`,
the same as archived v1.0.29 rows. This 10k lane does not calculate HBA. Its
canonical-SMILES spelling agreement with RDKit is only 64/10,000; semantic
round-trip is 10,000/10,000, so spelling is not treated as a chemical error.
The chemistry summary still has 69 unadjudicated classifications: integrity
and safe outcome accounting do not close every accuracy judgment.

The 63-operation Python matrix has 210,410 retained values per version and no
operation errors. The [rowwise differential](../validation/results/v1.0.29-to-v1.0.30-python-63op-diff.json)
finds changes only in `hba` and `lipinski_bundle(mw,logp,hbd,hba)`, 1,359 rows
each; the other **61 operations have zero value differences**. The v1.0.30
named HBA comparison is 5,000/5,000 against RDKit, versus 3,641/5,000 on
v1.0.29. Both compressed per-input files and the [v1.0.30 matrix](2026-10-02-v1.0.30-python-op-matrix.json)
are retained. The ordinary matrix's three-repeat timings retain their
unbalanced-order *diagnostic* status.

Correction: this npm/WASM package **does expose** `run_reactants`. Python,
Rust and npm all reproduce the historical 57/57 product-graph fixture result.
The new [83-row stratified report](../validation/results/v1.0.30-published-reaction-83-strata.json)
includes those 57 and covers maps, aromaticity, H, charge, multiple products,
isotopes, stereo and invalid inputs. Published Python has 75 semantic matches,
three jointly invalid inputs and **five wrong-confident outcomes**; Rust has
75 semantic matches, three typed invalid-input refusals, one diagnosed
valence-filtered outcome and four wrong-confident outcomes. Missing ether-map
orientations, unlabeled isotope matching and stereo semantics are visible in
the per-case rows. Product atom provenance has **not** yet been compared with
RDKit; no reaction yield or selectivity assertion is made.

The later [published npm 83-case report](../validation/results/v1.0.30-published-reaction-83-all-bindings.json)
finds 74 semantic matches, three jointly invalid inputs, five wrong-confident

`a43cf9eec38b04664dc8ee269aa69f51a9ae3e310fa5a781177d07f389e85785`.

The **unpublished source candidate** on this branch keeps both atom-map

## Paired speed diagnostics

The [version-paired runner](../scripts/bench_published_python_versions.py)
uses 20 AB/BA alternating blocks, separate interpreters, one untimed warmup
per arm, all raw observations, 4,000-resample paired-bootstrap 95% intervals,
and whole-process peak RSS. `B/A` below means v1.0.30 throughput divided by
v1.0.29 throughput (time A / time B). The v1.0.29 HBA output is **different**, so
its timing cannot establish an equivalent-output win.

| Published v1.0.29 → v1.0.30 | Median B/A | Bootstrap 95% interval | Scope |
|---|---:|---:|---|
| Parse only, 10k calls/block | 0.983 | 0.965–1.000 | Outputs equal; negligible single-host difference |
| Compatible Morgan, prepared 5k | 0.998 | 0.987–1.007 | Outputs equal; interval crosses parity |
| Compatible Morgan, parse-inclusive 5k | 1.015 | 0.825–1.149 | Outputs equal; wide interval crosses parity |
| Compatible Morgan, precomputed 5k | 1.016 | 0.780–1.239 | Outputs equal; wide interval crosses parity |
| Ring count, first-use perception 5k | 0.993 | 0.973–1.014 | Outputs equal; interval crosses parity |
| Ring count, parse-inclusive 5k | 0.992 | 0.983–1.000 | Outputs equal; near parity |
| Named HBA, prepared 5k | 1.007 | 0.991–1.019 | Outputs differ by design; no speed win |

The corrected parse-only benchmark does **not** serialize back to canonical
SMILES. An earlier local parse+writer draft ran under concurrent build load;
it was discarded and is not an archived result. Whole-process peak RSS is
present in raw blocks but is not net operation allocation or a cross-binding
memory claim.

On v1.0.30 versus RDKit 2026.03.6, 20 alternating blocks give:

| Operation | Median RDKit/CheMatic | Bootstrap 95% interval | Output gate |
|---|---:|---:|---|
| Named HBA, prepared 5k | 17.79 | 17.31–18.28 | 5,000/5,000 exact |
| Compatible Morgan, prepared 5k | 3.09 | 3.07–3.10 | 5,000/5,000 exact |
| Parse only, 5k | 20.88 | 20.63–21.12 | Same nominal task but RDKit sanitizes eagerly; **not equivalent work** |

These are Python-call, single-host, corpus-specific timings. They do not prove
a universal speed advantage. In particular, RDKit's eager perception and
CheMatic's lazy perception require parse-inclusive and precomputed lanes to be
reported separately before an end-to-end claim. npm/Rust 63-operation
capability matrices, matched memory work, equivalent perception boundaries,
cross-host replication, reaction map/provenance parity, and adjudication of
the 83-row residuals remain open.

Four additional RDKit comparison lanes separate prepared versus parse-inclusive
ring work. The prepared ring-count median is 0.33x and aromatic-ring count
0.15x, while parse-inclusive medians are 20.90x and 9.58x. **None qualifies
as an equivalent-output speed win**: RDKit agrees on only 4,946/5,000 ring
counts and 4,940/5,000 aromatic-ring counts in this cohort. Eager/lazy
perception also makes the work boundary different. The
[raw paired ring record](2026-10-02-v1.0.30-vs-rdkit-paired-ring-lanes.json)
retains all 20 blocks and uncertainty per lane.

A separate [63-operation paired Python matrix](2026-10-02-v1.0.30-vs-rdkit-python-63op-paired20.json)
has now completed on the published v1.0.30 wheel with 20 alternating blocks
and per-operation 95% paired-bootstrap intervals. Of 44 output-checked
operations, 22 have full output agreement and a faster median than RDKit; 20
also have an interval wholly above parity. This is a **single-host Python-call
diagnostic**, not an end-to-end 20-operation speed victory: prepared-input
lanes charge RDKit's eager perception to parsing and CheMatic's lazy work to
the call. Non-equivalent lanes and operations with output differences are not
counted. The previous 21-operation headline remains historical rather than
being silently replaced. The paired JSON SHA-256 is
`5448fd34190d5358227663a77e415e31dca71718cfd38c2d01e156ab539719da`.

## Reproduction entry points

Install each exact published wheel in a separate virtual environment. The
Python chemistry and operation commands use the pinned RDKit wheel and write
into a fresh output directory; never overwrite the archived results.

```sh
python3 scripts/run_rdkit_python_chemistry_lane.py --corpus validation/benchmark_corpora/rdkit-js-browser-10k-v1.smi --queries validation/rdkit_rebaseline_smarts_queries.json --expected-rdkit 2026.03.6 --rows-output OUT/python-rows.jsonl --output OUT/python-summary.json
python3 scripts/emit_rdkit_smarts_oracle.py --corpus validation/benchmark_corpora/rdkit-js-browser-10k-v1.smi --queries validation/rdkit_rebaseline_smarts_queries.json --expected-rdkit 2026.03.6 --output OUT/rdkit-smarts.jsonl
python3 scripts/bench_python_op_matrix_vs_rdkit.py --corpus scripts/chembl_accuracy_corpus_4999.smi --limit 5000 --outputs-only --output-values-jsonl OUT/op-values.jsonl --output-json OUT/op-summary.json --chematic-revision v1.0.30 --chematic-artifact WHEEL
python3 scripts/bench_python_op_matrix_vs_rdkit.py --corpus scripts/chembl_accuracy_corpus_4999.smi --limit 5000 --repeats 20 --paired --output-json OUT/op-paired20.json --chematic-revision v1.0.30 --chematic-artifact WHEEL
```

For npm, unpack the exact registry tarball to `OUT/npm/package` and run the
Node lane with all pinned inputs. The Python reference argument is a gzip file;
the SMARTS oracle argument is an uncompressed JSONL file. The runner verifies
both and writes every output row.

```sh
node scripts/run_published_npm_chemistry_lane.mjs --package-dir OUT/npm/package --tarball OUT/kent-tokyo-chematic-1.0.30.tgz --corpus validation/benchmark_corpora/rdkit-js-browser-10k-v1.smi --queries validation/rdkit_rebaseline_smarts_queries.json --python-reference validation/results/v1.0.30-published-python-chemistry-rows.jsonl.gz --smarts-oracle OUT/rdkit-smarts.jsonl --expected-rdkit 2026.03.6 --expected-version 1.0.30 --rows-output OUT/npm-rows.jsonl --output OUT/npm-summary.json
node scripts/run_published_npm_reaction_v2.mjs --base validation/reaction_product_parity_cases.json --strata validation/reaction_product_parity_strata_v2.json --package-dir OUT/npm/package --tarball OUT/kent-tokyo-chematic-1.0.30.tgz --output OUT/npm-reaction-83.json
cargo run --manifest-path tools/published_rust_gate/Cargo.toml --release --locked --bin published-chematic-gate -- validation/benchmark_corpora/rdkit-js-browser-10k-v1.smi validation/rdkit_rebaseline_smarts_queries.json OUT/python-rows.jsonl OUT/rdkit-smarts.jsonl OUT/rust-rows.jsonl OUT/rust-summary.json
cargo run --manifest-path tools/published_rust_gate/Cargo.toml --release --locked --bin reactions -- validation/reaction_product_parity_cases.json validation/reaction_product_parity_strata_v2.json OUT/rust-reaction-rows.json OUT/rust-reaction-summary.json
```

The standalone [`tools/published_rust_gate`](../tools/published_rust_gate)
workspace uses crates.io dependencies from its checked-in lockfile, not a
path dependency on the checkout. `OUT` and `WHEEL` above are caller-selected
paths; run each version in a separate interpreter to avoid importing the
wrong installed wheel.
