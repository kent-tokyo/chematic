## Crowded 2D layouts

| 15,000 rows, as drawn (`depict_data`) | Batch 16 | Source | RDKit |
|---|---:|---:|---:|
| clean (no clash, no crossing) | 14,669 | **14,699** | 14,504 |
| with a clash | 53 | **26** | 276 |
| with a crossing | 319 | **300** | 402 |
| bond off by > 20% | 278 | 276 | 540 |
| narrow branch atoms (rows) | 2,396 (320) | 2,291 (320) | 0 |

Against batch 16, no row has more defects. There are three changes:

- **Turns about ring double bonds.** The clash relief turns a branch only
  about an atom without a double bond, so that E/Z drawings survive. In the
  layout's own pass, which runs before any E/Z is set, a double bond in a
  ring no longer counts. This covers a Kekulé-written aromatic ring and a
  ring P=N: a carboxyl stacked on a Kekulé-written ring, or aziridines on a
  cyclophosphazene, could not be turned away before. The pass after the
  E/Z reflections still never turns about a double-bond atom.
- **Stress majorization for fused and spiro systems.** Batch 15's stress
  majorization now also redraws fused and spiro systems of three or more
  rings whose polygons overlap (cephalotaxine cores, spiro naphthodioxins,
  fused metal chelates, helicenes). As before, the result is kept only when
  it overlaps less.
- **Fewer narrow forks.** Some components of up to 60 atoms take the narrow
  ±30° forks. In those, only the forks within two bonds of the 120° drawing's
  defects stay narrow, when that does as well. Larger components (long
  peptides) keep the component-level choice, because relieving more
  candidates there costs about 30% of `write_mol`.

The new cases in `bridged_and_crowded_layouts_have_no_clash_or_crossing`
fail on the batch-16 layout.

The 26 rows left are mostly octahedral metal complexes, where RDKit clashes
too: four pyridines and two thiocyanates on one metal are spread 60° apart.
The rest are fullerene adducts (RDKit 1), two hexamine cages and a
porphyrin.

## Layout speed

`write_mol` on the first 2,000 exposed-10k rows (parse included):

| | Instructions |
|---|---:|
| batch 15 | 625M |
| batch 16 | 666M |
| source | **653M** |

The output-identical changes below gave 666M → 627M. The layout changes
above then cost 26M for the fused-system redraw (as a guard) and the
narrow-fork comparison, so the net is 653M. MOL blocks are
byte-identical on all 15,000 exposed-10k and ChEMBL-5k rows before the
layout changes above:

- The relief's grids are flat arrays rather than hash maps of cells.
- The bond-crossing test skips its square roots when an L1 bound already
  decides the sign.
- Cell indices truncate instead of calling `floor`.
- Branch sides and sorted neighbours are computed once per relief call, and
  move buffers are reused.

The fused-system redraw checks for an overlapping pair before building its
distance matrix.

## Depiction speed against RDKit

Python, exposed 10k (10,000 rows; 1,687 with stereo):

| | chematic source | PyPI v1.0.36 | RDKit |
|---|---:|---:|---:|
| `svg()` vs `MolDraw2DSVG` (all rows) | 991 ms | 508 ms | 11,762 ms |
| `depict_data()` vs `Compute2DCoords` | 631 ms | 323 ms | 2,954 ms |
| `to_mol_block()` vs `MolToMolBlock` | 550 ms | 181 ms* | 4,305 ms |
| `svg()`, stereo rows | 335 ms | — | 3,881 ms |

*v1.0.36 wrote molecules without stereo with every atom at the origin, so it
skipped their layout.

chematic is 5–12× faster than RDKit on every depiction path. Against
v1.0.36 it takes about twice as long. That cost buys the stereo depiction
(batch 15) and the 2D layout quality of batches 14–17: v1.0.36 drew 10,619
of 15,000 rows clean.
