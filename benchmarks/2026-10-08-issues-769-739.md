# #769 and #739: over-valent oxygen in SMILES, and the A6 penam stereo failures

Follows [batch 23](2026-10-08-734-754-followups-batch23.md). Linux x86-64
(glibc); RDKit 2026.03.6;
[summary](../validation/results/issues-769-739-2026-10-08.json).

## #769: neutral three-coordinate oxygen

The SMILES parser accepted `O=O1C=CC=C1`, and aromaticity perception then
aromatized the ring through the oxygen. It also accepted `CO(C)C`, `C=O=C`,
`[OH3]`, `c1cco(C)c1` and `F(C)C`. The parser did no valence check at all.

**Now.** A neutral oxygen with more than two bonds, or a neutral fluorine with
more than one, fails with `SmilesError::InvalidValence { element, atom,
valence, max }`. In Python it is `ChematicInputError` with category
`malformed` and code `smiles_valence`.

How the valence is counted:

- bond orders plus explicit hydrogens;
- an aromatic bond counts one, so a furan oxygen has two;
- a dative bond counts at its acceptor only;
- zero-order and query bonds count nothing.

What is not checked:

- charged atoms (`[O+]`, `[o+]`);
- the hypervalent states of S, P, N and the heavier halogens. Sulfones,
  nitro written `N(=O)=O` and N-oxides keep parsing.

Every input the check rejects is rejected by RDKit too.

**Corpora.** 226,477 SMILES in the repository's data files were parsed
before the change. One of them is now rejected: an NCI entry,
`CCO1=O=C1C2=CC=C(O2)C(C)(C)C`, which RDKit rejects too. It is in the NCI
first 5k and the browser candidate list, and in no gate corpus.

**Templates.** The BioTransformer gate found a regression. Rule BTMR0839
writes its product oxygen as `[#8;A;H1X2:1]` between two ring atoms. The
SMIRKS reader reads each template side as SMILES, so the rule now failed to
parse and refused all 400 reactants.

A template atom is a pattern, not an atom of a molecule, and RDKit does not
sanitize templates. SMIRKS templates are therefore read with the new
`chematic_smiles::parse_template`, which skips the check. A product that
would carry the impossible atom is still refused when the template is
applied (`product_valence`). Reaction SMILES of molecules (`parse_reaction`)
keep the check.

**Gates on the source wheel.** All of these equal the v1.0.37 expected
counts, with no differences:

- reaction 83;
- SMARTS 310k;
- CIP, hybridization, MMFF94 typing and the MOL writer;
- BioTransformer (1,051 implicit-H and 6,604 explicit-H rows exact).

xsmarts-autoconf gives 75/83 with 0 unexpected.

## #739: rows 53 and 246

**Reproduced.** Each wheel was run on the A6 protocol: seed 20260801, 8
attempts, 200 iterations, stereo-safe MMFF94. The rows were scored with
`pipeline_v2_vs_rdkit_common_scorer` and gated with the new
`scripts/a6_platform_gate.py`.

| Linux build | Successes | Sound | Stereo-clean | Clash | Failed rows |
|---|---:|---:|---:|---:|---|
| published v1.0.31 (cp39, glibc math) | 263 | 263 | 263 | 0 | 53, 246 (`FinalStereoViolation`) |
| published v1.0.37 (cp39, `libm` crate) | 265 | 265 | 265 | 0 | — |
| source, with glibc math put back in `fmath` | 263 | 263 | 263 | 0 | 53, 246 |
| source, glibc math, with the fix below | 265 | 265 | 265 | 0 | — |
| source with the fix (`libm`) | 265 | 265 | 265 | 0 | — (coordinates identical to v1.0.37 on all 265 rows) |

Row 53 is `penicillin_core`. Row 246 is `chembl_tier_b_0181`, a penam
sulfone.

**Matched host.** The builds below ran on the same Linux host. v1.0.31 and
the glibc-math build use glibc's functions; v1.0.37 uses the `libm` crate.

- **MMFF94 inputs.** The numeric atom types and charges are identical in all
  three builds.
- **Before minimization.** Stereo is satisfied in every build, before and
  after the repair stage.
- **Embedding.** The divergence starts here. The torsion-optimized energy
  of row 53 is 31.47 with glibc and 34.24 with `libm`; row 246 gives 36.46
  and 21.88.
- **Glibc starts.** From the glibc starts, which are strained (MMFF94
  736 and 801 kcal/mol), minimization stops on the stereo constraint
  (`constraint_rejected_fallback`) after 39 and 97 iterations. The
  heavy-atom verifier then finds the bridgehead inverted: atoms 4 and 13 of
  row 53, atom 24 of row 246.
- **libm starts.** From the `libm` starts, row 53 converges and row 246
  stops at the iteration limit, both satisfied.

**The `libm` change only moved the failure.** Over 300 seeds, the published
v1.0.37 wheel fails `penicillin_core` on 69 and `chembl_tier_b_0181` on 85
with `FinalStereoViolation`. Over ten seeds of all 265 A6 rows, 32 of 2,650
runs fail, on 15 rows: 13 penams, a bis-quinolinium macrocycle (an E
double bond) and a steroid with a fused ether ring. Seed 20260801 happens
to pass with `libm` and fail with glibc.

The defect is that a stereo-safe run has no way back once MMFF94 relaxes a
declared centre (here mostly a penam bridgehead) through inversion. The BFGS run, the L-BFGS retry and the
post-minimization repair can all leave the centre inverted. The pipeline's
existing reseed covered only a minimization that stalled on its constraint
and still returned a success. A run that failed went straight to the
caller.

**Fix.** A `RepairAndVerify` run that ends in `FinalStereoViolation` now
embeds again:

- from up to seven other seeds, within the time budget;
- it returns the first success;
- when every seed fails, it returns the first failure unchanged, so the
  typed refusal stays.

A run that succeeds at its own seed is unchanged. `VerifyOnly` and `Ignore`
are unchanged too. A guarded re-minimization from the same start was tried
first and changed nothing: these starts are already minimized under the
stereo constraint.

| | Before | After |
|---|---:|---:|
| `penicillin_core`, 300 seeds, failures | 69 | 0 |
| `chembl_tier_b_0181`, 300 seeds, failures | 85 | 0 |
| 265 A6 rows × 10 seeds, `FinalStereoViolation` | 32 / 2,650 | 0 / 2,650 |
| the same with glibc math | — | 0 / 2,650 |

At 1,000 iterations, the single-conformer arm is identical to v1.0.37 on
all 265 rows. The lowest-of-10 arm changes on 2 rows, now that more of their
attempts succeed:

- at or below RDKit's best: 158 → 159;
- median, p90 and within 1 kcal/mol: unchanged (0.00 / 3.69 / 198).

**Regression tests.** `crates/chematic-3d/tests/issue739_platform_stereo.rs`
runs the seeds that failed with v1.0.37:

- five of `penicillin_core`;
- three of `chembl_tier_b_0181`;
- four of `chembl_tier_b_0175`.

It requires a success, fully satisfied stereo, a sound geometry and no
clash. It also checks that `VerifyOnly` still reports the violation.

**CI.** The A6 steps of the Linux, macOS and Windows source-wheel jobs now
gate on the independent scorer. Each requires 265 successes, all sound,
stereo-clean and clash-free.

- The published-wheel A6 jobs (Linux and macOS, Python 3.9) pin v1.0.37
  instead of v1.0.31.
- A new job compares the macOS and Windows coordinates with the Linux ones
  row by row. It reports the result and does not gate on it.
- The published-wheel chemistry workflow runs the A6 rows on the macOS and
  Windows wheels and scores them on Linux.
- The v1.0.37 expected file records the Linux wheel's coordinate digest
  (`b1ce930f…`).

**Other platforms (published v1.0.37, emulated on this host).** The
Linux aarch64 wheel was run under `qemu-aarch64` and the Windows amd64 wheel
under Wine, both with CPython 3.9.23.

| v1.0.37 wheel | A6, seed 20260801 | Coordinates equal to Linux x86-64 | 10 seeds × 265 rows |
|---|---|---:|---|
| Linux x86-64 (native) | 265 / 265 sound, stereo-clean, clash-free | — | 32 / 2,650 `FinalStereoViolation` |
| Linux aarch64 (qemu) | 265 / 265 | 265 / 265 rows | the same 32 runs (same rows and seeds) |
| Windows amd64 (Wine) | 265 / 265 | 265 / 265 rows | the same 32 runs |

With the `libm` crate, the coordinates are bit-identical across the three
builds, including a different instruction set. Wine supplies the C runtime,
but v1.0.37 takes its transcendental functions from `libm`. The penam
failures are the same on every build, which is why the fix is the
re-embedding and not more math changes. macOS still needs the CI jobs: this
host cannot run a macOS binary. Speed is not part of this record, as #739
asks.
