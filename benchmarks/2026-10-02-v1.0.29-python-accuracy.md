This is an **exposed-corpus, single-host, Python-only partial P0 packet**. It
does not re-use sealed A0 data, prove broad SMARTS/SMIRKS compatibility, or
establish a cross-binding speed win. The HBA correction described below is
**unreleased source**, not part of the measured v1.0.29 wheel.

## Published-wheel result

| Gate | v1.0.29 wheel vs pinned RDKit | Boundary |
|---|---:|---|
| SMILES read and semantic round trip | 10,000/10,000 | Only 64 canonical strings are identical; spelling is not the semantic gate |
| Accurate CIP | 9,995 exact; five typed abstentions | Four `oracle_unstable` P, one `lone_pair_center`; no wrong confident label in this cohort |
| Compatible Morgan | 9,999 exact; one typed refusal | Fe(II) coordination outside supported profile |
| SMARTS | 200 differences / 310,000 cells | Existing classified residual: 194 ring-model, six ferrocene |
| Reaction products | 57/57 fixture product sets | Six #679 cases added; not broad reaction precision/recall |
| Named RDKit HBA | 3,641/5,000 exact | Regressed against 2026.03.6; native HBA independently measured 5,000/5,000 |

The v1.0.28 and v1.0.29 published wheels produced byte-identical JSONL
chemistry rows on this 10,000-input lane (raw SHA-256
`e9b8592b69a0663608ab51d0d83d3db644a515a7cbfedefe5ad5aff61780b968`).
That lane does **not** contain the #679 reaction or #680 repeated-charge
queries. The reaction gate compares RDKit-sanitized product graphs after
canonicalization, preserves multiplicity within each product tuple, and
reports missing/extra product sets. It rejects a template if the RDKit oracle
emits an unsanitizable product; the invalid aromatic-N methylation example was
not counted as parity. The repeated-charge parser remains covered by focused
Rust/Python regressions, not by this 310k-cell generalization.

The 5k [operation matrix](2026-10-02-v1.0.29-python-op-matrix.json) covers
63 operations; 44 are output-checked. Twenty-one of those have full output
agreement and a faster median of three repeats. Every chematic timing repeat
preceded every RDKit repeat in one process, without counterbalancing or a
confidence interval. Treat the timing as diagnostic, not a formal speed gate;
the two libraries also differ in parse-time versus lazy perception work.

## Unreleased correction

RDKit [#8997](https://github.com/rdkit/rdkit/issues/8997) changed the
aromatic-N acceptor rule: substituted three-neighbor aromatic N is excluded
by the pinned RDKit 2026.03.6 HBA definition. The named compatibility API
still used the older rule. On the same published wheel and 5k rows, native
`Mol.hba` agrees 5,000/5,000 with RDKit while `Mol.rdkit_hba` agrees
3,641/5,000. The source fix makes `rdkit_hba_count` share the native rule;
caffeine changes from six to three in the named Python API and the WASM
RDKit-profile descriptor. Rust chemistry tests: 885 passed, one pre-existing
ignored. A **dev-profile source wheel** built from this branch was imported
and directly compared with RDKit 2026.03.6 on all 5,000 rows: named and
native HBA each matched 5,000/5,000, with zero parse failures. The raw
[source-wheel report](../validation/results/rdkit-hba-source-dev-wheel-5k-2026-10-02.json)
records wheel SHA-256
`b03642d52f4312c9f55221a70bdb7403cd6373fc4b0095b87ea2df7a04dc83e1`.
The local macOS **release-profile wheel** did not import (`mis-aligned LINKEDIT
string pool`); the CI release-profile wheel gate and a later published-artifact
rerun remain necessary. Neither wheel is the published v1.0.29 artifact.
