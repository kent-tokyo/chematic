Follows [batch 20](2026-10-08-734-754-followups-batch20.md). This batch

## Typed abstention across bindings

`scripts/typed_abstention_audit.py` (Python) and
`scripts/typed_abstention_audit.mjs` (WASM package) probe each operation
family with an input built for one abstention category: `malformed`,
`unsupported`, `ambiguous` or `resource_limit`
(`validation/results/typed-abstention-audit-*-2026-10-08.json`).

- **Already typed.** Reactions (`status: typed_refusal` with `reason`), the
  3D pipeline (Python `PipelineV2Error.diagnostics.cause`, WASM
  `error.cause.kind`) and the nucleic-acid document model (`error.code`)
  report a stable kind in both bindings.
- **Parsers, before this batch.** SMILES, SMARTS, MOL, InChI and mmCIF
  reported text only.
- **Python, now.** These parsers raise `chematic.ChematicInputError`, a
  `ValueError` subclass:
  - `category`: `malformed`, or `resource_limit` for an input past a declared
    limit;
  - `code`: `smiles_parse`, `smarts_parse`, `mol_block_parse`, `inchi_parse`,
    `mmcif_parse`, `input_too_large`, `line_too_long` or `too_many_atoms`;
  - `format`.

  `except ValueError` keeps working. Test: `tests/test_input_errors.py`.
- **WASM.** The parsers still throw strings. Thrown `Error` objects would
  change what callers comparing the thrown value see, so that change is left
  for a release that may change the error surface (decided with the
  maintainer).
- **Matrix.** `docs/error-and-limits.md` holds the matrix.

## Nucleic-acid edit sequences across runtimes

`validation/nucleic_acid_edit_sequences.json`
(`scripts/nucleic_acid_edit_sequences.py`) holds three command sequences from
the contract's valid documents, 14 steps in all. They include:

- a missing target (`missing_target`);
- an unknown base (`invalid_command`);
- an unknown modification (`unknown_modification`);
- an empty annotation key (`invalid_command`).

Each step records the edited document, or the typed error with the document
left unchanged. The Rust test, the Python test and
`crates/chematic-wasm/tests/nucleic_acid_edit_sequences.test.mjs` replay the
sequences. Each runtime must return the same envelopes and a document that
validates again after serialization. Atom ownership must stay unchanged:
every atom owned by exactly one residue, as at the start. The sequences pass
on the Rust crate, the source Python wheel and the published npm 1.0.37
package.

## Depiction speed, published v1.0.37

`scripts/depiction_speed_vs_rdkit.py` parses the exposed 10k (10,000 rows)
and times only the depiction calls, as the minimum of three passes. The
chematic calls are `svg()`, `depict_data()` and `to_mol_block()`. The RDKit
2026.03.6 calls are `MolDraw2DSVG(300, 300)`, `Compute2DCoords` and
`MolToMolBlock` on a copy without conformers, so that it lays out as
`to_mol_block` does.

| Exposed 10k | PyPI v1.0.37 (Linux, CPython 3.9) | Source (this branch) | RDKit 2026.03.6 (CPython 3.11) |
|---|---:|---:|---:|
| SVG | 765 ms | **569 ms** | 9,655 ms |
| 2D coordinates | 633 ms | 628 ms | 2,742 ms |
| MOL block | 518 ms | 494 ms | 3,869 ms |

The published v1.0.37 wheel is 12.6× (SVG), 4.3× (coordinates) and 7.5×
(MOL block) faster than RDKit on this host. The source's SVG is faster still
because of batch 19's fixed two-decimal writer. These are wall times of one
process on one host (Linux x86-64), not the paired fresh-process protocol of
the P0.2 lanes.
Results: `validation/results/depiction-speed-*-2026-10-08.json`.
