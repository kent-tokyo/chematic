# v1.0.6 local-source hot-path follow-up

Measured 2026-09-05 on Apple M4 (16 GiB), macOS 26.5.2 arm64, Rust/Cargo
1.97.0. Version remains **1.0.6**. This is a source-level A/B comparison,
not a published-wheel measurement or a new RDKit/Open Babel comparison.

## Result

Canonical SMILES and both SDF lanes exceeded the additional **1.10x** target
at the median of paired ratios. SMILES parse did **not** meet that target.

| Lane | Baseline median (us/molecule) | Candidate median | Median paired speedup | Paired range |
| --- | ---: | ---: | ---: | ---: |
| SMILES parse | 7.663 | 6.858 | 1.034x | 0.763–1.501x |
| Canonical SMILES (preparsed) | 49.299 | 43.680 | **1.176x** | 1.064–1.227x |
| File-backed SDF graph/property read | 22.811 | 19.231 | **1.180x** | 0.914–1.932x |
| SDF serialization, reused buffer | 3.244 | 2.275 | **1.419x** | 1.334–2.309x |

Per-side medians are descriptive; their quotient need not equal the median
paired ratio. Read/parse had notably unstable samples under concurrent host
load. These results support a scoped local improvement, not a universal
1.10x guarantee for every corpus, machine, binding or API.

## Measurement contract

- Baseline: frozen before this task's changes, based on HEAD
  `5d26d5f1c88d736fe49c92a98a41d9177f167b04` plus pre-existing local changes.
  Those unrelated changes are retained on both sides.
- Release profile: opt-level 3, LTO, one codegen unit; same toolchain and
  dependency lock. Cargo.lock SHA-256:
  `ca289c1dc0046d3fecb92fb83dae59205a6b7eef24bcac95fda542982e0ade96`.
- 5,000 SMILES from `scripts/chembl_accuracy_corpus_4999.smi`; despite its
  historical filename, the measured count is 5,000. SDF uses 365 records from
  RDKit's installed `Contrib/PBF/testData/egfr.sdf`.
- Seven alternating AB/BA process pairs; each process warms up each lane,
  times five rounds of ten corpus passes, then returns the round median.
  Headline speedups use the median of the **paired ratios**, not the ratio
  of independently selected best times. All pairs, including outliers, remain
  in the [raw report](2026-09-05-hotpath-110.json).
- Canonical timing excludes initial parsing. Read includes file open/read,
  graph/property parsing and collection via `SdfFileReader::fast`; it does
  **not** include full stereo/coordinate diagnostics. Write includes full SD
  properties into a reusable `String`, without layout, coordinates or disk
  output. This does not measure all parsing/writing APIs or 3D pipelines.
- No build/test was run concurrently with the final benchmark, but unrelated
  renkin/system tasks were active. This is not an isolated-host performance
  guarantee; the raw paired range documents substantial load variability.

## Retained implementation

1. Index SMILES ring labels directly (0..99), use an inline close-partner
   buffer with heap spill, and skip scanning the table when all rings closed.
   Unique occurrence slots still distinguish repeated ring labels.
2. Reuse the last canonical refinement pass's sorted distinct ranks for
   ordinal normalization, instead of allocating and sorting another vector.
3. Specialize common V2000 integer, element, zero-Z and neutral atom fields;
   retain generic parsers/formatters for other spellings and values. Decimal
   output fields are validated as UTF-8 at compile time; no new unsafe code.
4. Read SDF lines directly into the record buffer, eliminating a second copy.
   Existing delimiter, UTF-8, diagnostic and resource-limit contracts remain.

The first runtime-UTF-8 table experiment regressed writer throughput (paired
median 0.819x over three exploratory pairs) and was replaced. Exploratory
numbers are not the final gate. The final benchmark executable grew from
970,944 to 985,888 bytes (+1.54%); this is an executable-size observation,
not a measurement of every binding's artifact size.

## Correctness and lint

- 928 Rust unit/integration tests passed across `chematic-smiles` and
  `chematic-mol`, including canonical idempotency on two 5,000-input corpora.
- All ASCII three-byte integer fields (128^3 combinations), fallback and
  Unicode errors, 0..1001 formatting, ring labels 0..99, label reuse and
  inline-buffer spill are checked.
- New streaming regression covers 1/2/3/7/8192-byte buffers, LF/CRLF,
  multibyte data, delimiter/EOF boundaries and exact resource-limit edges.
- Exact baseline/candidate dump equality is checked before timing, outside
  the measured region. It includes canonical strings and SDF graph/header
  serialization plus sorted properties (HashMap iteration order is not a
  byte-order contract). The raw report records SHA-256, not just a checksum.
- A second 5,000-input corpus (`scripts/descriptor_census_corpus.smi`) also
  passed exact baseline/candidate dump comparison, including the same SDF
  records: 1,695,604 bytes, SHA-256
  `44934e1ceae7bfcd4f922f54652805a6d100ba3075485f26093746206bba5a03`.
- Four Python runner tests passed: alternation/resume, changed-binary refusal,
  byte mismatch, interruption recovery and non-finite timing rejection.
- `cargo clippy -p chematic-smiles -p chematic-mol --all-targets --offline
  --locked -- -D warnings`, scoped `rustfmt --check`, and `git diff --check`
  passed. This is not a fresh full-workspace or all-binding validation claim.

## Reproduction

Build `crates/chematic-mol/examples/hotpath_throughput.rs` with:

```sh
cargo build -p chematic-mol --example hotpath_throughput --release --offline --locked
```

Retain the candidate executable. In a **separate disposable copy** of the same
source/dependency state, reverse [the scoped optimization patch](2026-09-05-hotpath-110.patch)
(`git apply -R ...`) and rebuild the same example to obtain a baseline.
The patch excludes unrelated local work; its reverse applicability was checked.
Do not reverse it over ongoing work in the main checkout.

```sh
python3 scripts/bench_hotpath_pair.py \
  --baseline /path/to/baseline --candidate /path/to/candidate \
  --smiles scripts/chembl_accuracy_corpus_4999.smi \
  --sdf /path/to/egfr.sdf --pairs 7 --repeats 10 --output /path/to/new-report.json

cargo test -p chematic-smiles -p chematic-mol --lib --tests --offline --locked
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s scripts/tests -p test_bench_hotpath_pair.py
```

The report saves completed pairs atomically and resumes only with identical
binary/input SHA-256 and configuration. Source/corpus changes require a new
output path. Missing external fixtures are errors, never silently skipped.
