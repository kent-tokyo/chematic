## Why this snapshot

The prior snapshot ([2026-07-17](2026-07-17.md)) pinned every number to
**v0.4.29** — ~14 minor releases behind the current workspace. This
snapshot re-measures everything fresh ahead of the v0.19.0 release, using a
now-committed corpus (`scripts/chembl_accuracy_corpus_4999.smi`, copied from
the personal `~/Downloads/SMILES.csv` path every prior snapshot depended
on) so these numbers are actually reproducible by someone other than the
original measurer.

## Startup time (`scripts/bench_startup.py --rdkit --runs 10`)

| | chematic | RDKit |
|--|----------|-------|
| `import` (median of 10 subprocess runs) | **14.6 ms** | 98.1 ms |
| `import` + first parse | **14.6 ms** | 103.3 ms |
| Speedup | **6.7×** | baseline |

Both sides are markedly faster in absolute terms than the 2026-07-17
snapshot (chematic ~35 ms → 14.6 ms; RDKit ~400 ms → 98.1 ms) — plausibly
RDKit 2026.03.4 vs .3, or environment/disk-cache differences, not
investigated further here. The *ratio* (6.7×) is the number to trust more
than either absolute figure across snapshots.

## WASM bundle size

```bash
cd crates/chematic-wasm
rm -rf pkg
wasm-pack build --target web --release   # wasm-pack 0.13.1
wasm-opt -O3 -o pkg/chematic_wasm_bg.wasm pkg/chematic_wasm_bg.wasm   # binaryen 130 (CI uses 119)
ls -lh pkg/chematic_wasm_bg.wasm
gzip -k pkg/chematic_wasm_bg.wasm && ls -lh pkg/chematic_wasm_bg.wasm.gz
```

| | chematic (`--target web`) | RDKit.js (`@rdkit/rdkit` 2025.3.4-1.0.0, npm) |
|--|--|--|
| Raw | **2,975,334 bytes (2.98 MB)** | 6,914,823 bytes (6.91 MB) |
| Gzip | **1,107,489 bytes (1.11 MB)** | 2,058,729 bytes (2.06 MB) |

RDKit.js measured by `npm pack @rdkit/rdkit` and inspecting
`package/dist/RDKit_minimal.wasm` directly — its previous "6.91 MB raw"
citation reproduces almost exactly; its gzip size (2.06 MB) is newly
measured, not previously published anywhere in this repo's docs.

**Important correction from this snapshot**: nothing on disk previously
reproduced the "2.94 MB raw / 1.10 MB gzip" figure cleanly — the closest
match (`pkg-node/chematic_wasm_bg.wasm`, 2,940,833 bytes) was built via
CI's `--target nodejs` path, not the `--target web` build the docs
attribute it to, and the actual `--target web` artifact on disk was a
different, older build with a stale `.gz`. This snapshot's numbers come
from a single, fresh, correctly-targeted build — see the exact commands
above.

## Descriptor accuracy vs RDKit 2026.03.4

### 4,999-mol ChEMBL corpus (`scripts/chembl_accuracy_corpus_4999.smi`, now committed)

Full 20-descriptor + stereocenter-oracle-calibration + CIP-label-agreement
breakdown: [`docs/validation.md`](../docs/validation.md) (regenerated via
`scripts/gen_validation_report.py` from this snapshot's own
`validation/results/bench5k_latest.json`).

Headline: 20 of 20 tested descriptor/count metrics reach ≥98.6%; a
separate CIP R/S/E/Z label-agreement measurement (not part of the
descriptor table — a different question, see `docs/validation.md`) reaches
99.74–99.78%, a large improvement over the 2026-07-17-era 96.30–96.83%.

**New this snapshot**: molecular weight now has a genuine, corpus-wide
check (99.82%, 4990/4999, ±0.01 Da vs `Descriptors.MolWt`) — `bench5k.py`
never actually measured MW before (only monoisotopic `exact_mass`);
`docs/validation.md`'s prior "175-mol reference" annotation was
hardcoded template prose, unconnected to any real measurement. Fixed at
the source (`scripts/bench5k.py`, `scripts/gen_validation_report.py`), not
just in this snapshot's prose.

**Also fixed this snapshot**: `gen_validation_report.py`'s "Oracle
disagreements" breakdown was pulling the wrong JSON fields (chematic-vs-
oracle deltas instead of legacy-vs-new-CIP oracle-internal disagreement
counts), which happened to sum correctly by coincidence in the last
snapshot's data but does not in this one (68 total disagreements; the
old formula would have reported "0 + 70" instead of the correct
"68 + 0"). See `docs/validation.md`'s Oracle Calibration section for the
corrected, self-consistent breakdown.

### How to reproduce

```bash
.venv/bin/maturin develop --release -m crates/chematic-py/Cargo.toml   # if the editable install is stale
.venv/bin/python scripts/bench5k.py scripts/chembl_accuracy_corpus_4999.smi --json validation/results/bench5k_latest.json
python3 scripts/gen_validation_report.py validation/results/bench5k_latest.json

# CIP R/S/E/Z label agreement (separate from the descriptor table above):
cargo run -p chematic-cip --release --example corpus_snapshot -- \
    --candidate scripts/chembl_accuracy_corpus_4999.smi /tmp/candidate.tsv
.venv/bin/python scripts/cip_accurate_full_corpus_report.py \
    /tmp/candidate.tsv /tmp/candidate.tsv scripts/chembl_accuracy_corpus_4999.smi
```

## 3D conformer generation — not remeasured, explicitly out of scope

No RMSD/TFD comparison against RDKit's ETKDGv3 exists anywhere in this
repo's docs, and this snapshot does not add one (explicitly out of scope
for this release cycle — see `docs/rdkit-migration.md`, which already
states this honestly: 3D conformer generation is **Experimental**, not
quantitatively compared). The previous `docs/benchmark.md` framed this as
"Good (ETKDG rules)" vs RDKit's "Better (ML-assisted)" — a graded-but-close
comparison this repo has no measurement to back. Corrected in this
snapshot's docs update to match the migration guide's own honest framing.

## Notes

- **Environment was broken before this snapshot**: the local `.venv`'s
  editable `chematic` install pointed at a deleted git-worktree path
  (`ModuleNotFoundError` despite `pip show` reporting a stale version).
  Fixed via `maturin develop --release -m crates/chematic-py/Cargo.toml`
  before any measurement here. If a future snapshot hits the same error,
  this is the fix.
- **The 4,999-mol corpus is committed for the first time** this snapshot
  (`scripts/chembl_accuracy_corpus_4999.smi`) — every prior snapshot back
  to 2026-06 depended on a personal `~/Downloads/SMILES.csv` path that
  nobody else could reproduce from. Same corpus identity/content, just now
  versioned in the repo.
- **The ECFP4 "diverse corpus" number now has a real, reproducible source**
  (`benchmark_vs_rdkit.py --corpus`, new this snapshot) — previously no
  committed script could regenerate the 2026-07-17 snapshot's 78.3 µs/mol
  figure at all (traced and confirmed during this snapshot's prep).
- Corpus used for the ECFP4/parse diverse-corpus measurements is
  `scripts/descriptor_census_corpus.smi` (5,000 molecules, already
  committed, previously used only by `scripts/descriptor_census.py`) — a
  different corpus from the 4,999-mol accuracy one above, chosen because it
  was already in the repo and exactly fits "real, diverse molecules." Do
  not conflate the two corpora.
- Rust-native `cargo bench` numbers (chematic-fp/chematic-perception,
  reported in the 2026-07-17 snapshot) were not remeasured this cycle —
  out of scope for this release-prep pass, which focused on the Python-API
  numbers actually cited in `docs/benchmark.md`/`docs/validation.md`.
- WASM per-operation (in-browser) timings were not remeasured this cycle —
  only bundle size. Same limitation as the 2026-07-17 snapshot.
