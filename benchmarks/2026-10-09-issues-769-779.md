## #779: Streamable HTTP transport

**What was added.** `chematic-mcp --transport streamable-http [--bind IP]
[--port N]` serves `POST /mcp`. Running `chematic-mcp` with no arguments is
stdio, exactly as before. Integration tests that drive the binary check
this.

The adapter (`crates/chematic-mcp/src/http.rs`) uses only `std::net`.

- It does HTTP framing and the transport's checks: path, method, `Host`,
  `Origin`, `Content-Type`, `Accept`, body length and mirrored headers.
- It then hands the body to a fresh `Connection` per request. The same
  codec, `McpServer` and tool registry as stdio answer it, so there is no
  second dispatcher.
- It serves the 2026-07-28 stateless dialect only. There are no sessions, no
  GET stream and no SSE. Each answer is one `application/json` object.

The README section "Streamable HTTP (opt-in)" has the options, the status
code table, the limits and the security notes.

**Security defaults.**

- The server binds `127.0.0.1:3000`.
- Binding a non-loopback address is refused without `--allow-non-loopback`.
  The check is in `HttpServer::bind`, so library users get it too.
- On a loopback bind, the `Host` header must be loopback. An `Origin` must be
  a loopback origin or one listed with `--allowed-origin`.
- No CORS headers are sent, and `OPTIONS` gets `405`.
- There is no authentication, OAuth, hosted endpoint or SLA. The README says
  so in the overview, in the capability table and in the HTTP section.

**Limits.**

- Bodies are limited to 1 MiB (stdio's `MAX_REQUEST_BYTES`), with the same
  depth checks as stdio.
- The request line is limited to 8 KiB and the headers to 32 KiB in total,
  with at most 100 fields.
- `Content-Length` is required (`411`); there is no chunked request body.
- Each connection has a 30 s read/write timeout (`408`).
- At most `--max-concurrency` connections (default 16) are served at once.
  Further connections get `503` with `Retry-After: 1`.

### Tests

`crates/chematic-mcp/tests/streamable_http.rs` has 11 tests. Each starts a
server on an ephemeral loopback port, and answers are compared with what
stdio returns for the same body:

- `server/discover`, `tools/list` and `tools/call` (`calc_properties`):
  `200`, and the body is identical to stdio, including `structuredContent`.
- Invalid arguments: `400` with `-32602`, identical to stdio.
- A typed chemistry error (`C1CC(`): `200` with `isError` and
  `INVALID_SMILES`.
- Mirrored headers:
  - a missing or different header gives `-32020`;
  - an unsupported version gives `-32022`;
  - the Base64 `Mcp-Name` form is decoded;
  - whitespace around a header value is ignored;
  - legacy `initialize`, or `_meta` without `protocolVersion`, gives `400`
    with `-32602`.
- `clientInfo` is optional: `200`, identical to stdio.
- An unknown method gives `404` with `-32601`.
- Limits:
  - a body over 1 MiB gives `413`;
  - deep nesting, a parse error and a batch each give `400`;
  - no `Content-Length` gives `411`;
  - the wrong `Content-Type` gives `415`;
  - the wrong `Accept` gives `406`.
- `GET`, `DELETE` and `OPTIONS` give `405` without CORS headers. The wrong
  path gives `404`. A notification gives `202`.
- `Origin` and `Host`:
  - foreign and `null` origins get `403`;
  - loopback origins and listed origins get `200`;
  - a rebound `Host` gets `403`.
- Concurrency: `503`, then served again once the held connection times out.
- A non-loopback bind is refused without the flag.
- The binary:
  - `--port 0` serves HTTP;
  - `--bind 0.0.0.0` is refused;
  - an HTTP-only flag without `--transport streamable-http` exits 2;
  - stdio with no arguments is unchanged.

Full `chematic-mcp` suite results: 90 lib tests, 21 schema-conformance tests
and 11 HTTP tests pass.

### Official conformance suite

`@modelcontextprotocol/conformance` 0.2.0-alpha.12 is the first release with
2026-07-28 server scenarios. All 40 of the server scenarios it tags
2026-07-28 were run against `chematic-mcp --transport streamable-http
--port 0`, each one on its own.

Against the first build, the suite found three real defects:

| Check | Was | Fix |
|---|---|---|
| `sep-2575-request-meta-invalid-missing-meta`, `…-missing-protocol-version` | `400` with `-32020` | A request whose `_meta` lacks `protocolVersion` is `400` with `-32602`, checked before the header comparison. |
| `sep-2575-request-meta-client-info-optional` | `-32602`: `clientInfo` was required, on stdio too | `clientInfo` is optional, as `RequestMetaObject` defines it. A malformed value is still `-32602`. |
| `localhost-host-valid-accepted` | `403` for a loopback `Origin` | Loopback origins are accepted on a loopback bind. |

Making `clientInfo` optional is the one change visible on stdio. Requests
that worked before work the same way. Requests that omit `clientInfo` are
now served instead of rejected.

After the fixes, 82 checks pass and the suite reports 41 failures. The table
below gives the scenarios with nothing left to fix, then what the remaining
failures are:

| Scenario(s) | Result |
|---|---|
| `tools-list`, `dns-rebinding-protection`, `sep-2164-resource-not-found`, `server-sse-multiple-streams`, `input-required-result-validate-input`, `…-unsupported-methods`, `…-missing-input-response`, `…-ignore-extra-params` | every check passes |
| `server-stateless` | 20 / 24. The 4 failures say "Not testable": they need the suite's `test_missing_capability`, `test_streaming_elicitation` and `test_logging_tool` |
| `http-header-validation` | 13 / 14. The remaining check calls the first listed tool (`parse_smiles`) with `arguments: {}`. Its padded `Mcp-Name` passed the header check and reached the input-schema check (`-32602`, missing `smiles`). The same padding with valid arguments returns `200` in our test |
| `caching` | 4 / 7. `tools/list` carries valid `ttlMs`/`cacheScope`; the 3 failures are for `prompts/list`, `resources/list` and `resources/templates/list` |
| `tools-call-*` (7), `json-schema-2020-12`, `http-custom-header-server-validation`, 9 `input-required-result-*` | need the suite's fixture tools (`test_*`, `json_schema_2020_12_tool`, tools with `x-mcp-header`) |
| `resources-*` (4), `prompts-*` (5), `completion-complete` | exercise capabilities chematic-mcp does not implement or advertise; `-32601`/`404` is the correct answer |

The 41 failures break down as:

- 26 need a suite fixture;
- 14 exercise a capability chematic-mcp does not implement;
- 1 calls a tool with empty arguments.

None is a chematic-mcp defect. In every scenario the
`wire-schema-valid` check passed: every message the server sent validates
against the 2026-07-28 schema.

**Warnings left open.**

- `sep-2575-server-identifies-in-result-meta` (SHOULD): `server/discover`
  keeps `serverInfo` at the top level, the shape decided against the RC pin
  in `validation/manifests/mcp_2026_07_28_rc.json`, and results carry no
  `_meta` `serverInfo`.
- The `sep-2164-*` and `sep-2322-*` warnings are about resources and
  input-required results, which are not implemented.

## Not done

- No SSE responses. Nothing this server sends needs them: no progress, no
  logging, no input requests.
- No legacy (2025-era) dialect over HTTP, and no sessions.
- No TLS and no authentication. Put a reverse proxy in front if you bind
  outside loopback.
- No hosted endpoint.
